# Internationalization (i18n)

Cashly ships two languages: **Spanish (default)** and **English**. Translations are bundled JSON files compiled into `src/app/core/i18n/dictionaries.ts`.

---

## Runtime model

| Piece                                                               | Responsibility                                                                         |
| ------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | --- |
| `LanguageService`                                                   | Current language (`es`/`en`), `es`/`en-US` locale, `<html lang>`, PrimeNG translations |
| `UserPreferencesService`                                            | Persists language per user and syncs it with the language service                      |
| `TranslationService`                                                | Resolves keys, source text, `${param}` templates, and `{{param}}` placeholders         |
| `TranslationPipe` (`translate`)                                     | Template helper around `TranslationService`                                            |
| `TranslateOptionsPipe`                                              | Translates option labels                                                               |
| `LocalizedDatePipe`, `LocalizedNumberPipe`, `LocalizedCurrencyPipe` | Locale-aware formatting                                                                |
| `TranslatedTitleStrategy`                                           | Translates route `title` values                                                        |
| `TranslatedMessageService`, `TranslatedConfirmationService`         | Translate toast and confirmation text                                                  |
| `languageInterceptor`                                               | Sends `Accept-Language: es                                                             | en` |

The active language starts as `es`, then follows the authenticated user's preference through an effect in `app.ts`.

---

## Translation files

Each feature keeps its own files:

```
src/app/features/<area>/<feature>/i18n/
├── en.json
└── es.json
```

Some features also have `messages/i18n/{en,es}.json` for toast and error contracts. Core and shared translations live in:

```
src/app/core/<area>/i18n/{en,es}.json
src/app/shared/i18n/{en,es}.json
src/app/shared/i18n/primeng/{en,es}.json
```

All of them are explicitly imported and merged in `src/app/core/i18n/dictionaries.ts`. **A new JSON file does not load automatically** — add its Spanish and English imports and include them in the `spanish` and `english` maps.

Use dotted namespaces that match the module path:

```json
{
  "platform.company.legalName": "Legal name",
  "partners.customers.creditLimit": "Credit limit",
  "shared.save": "Save"
}
```

Spanish is the source catalog: `TranslationService` can also resolve by the Spanish source text and can match parameterized templates.

## Usage

### Templates

```html
<h2>{{ 'partners.customers.title' | translate }}</h2>

<p-button [label]="'shared.save' | translate" />

<span>{{ 'partners.customers.creditDays' | translate: { days: customer.creditDays } }}</span>
```

`TranslatePipe` is impure so it re-evaluates when the language changes.

### TypeScript

```typescript
private readonly translations = inject(TranslationService);

readonly title = computed(() => this.translations.t('finance.billing.invoices.title'));
readonly message = this.translations.t('shared.savedWith', { name: invoice.invoiceNumber });
```

### Options

```html
<p-select [options]="options | translateOptions" optionLabel="label" optionValue="value" />
```

`translateOptions` translates `label` fields and can limit translation to placeholder options.

### Dates and numbers

```html
{{ invoice.issueDate | localizedDate: 'dd/MM/yyyy' }} {{ invoice.total | localizedCurrency: 'USD' }}
{{ product.stock | localizedNumber }}
```

`localizedDate` swaps `dd/MM/yyyy` for `MM/dd/yyyy` in English.

### Route titles

```typescript
{ path: 'customers', title: 'partners.customers.title' }
```

`TranslatedTitleStrategy` translates the title and falls back to `Cashly`.

### Toasts and confirmations

The app config registers `provideTranslatedMessages()` and `provideTranslatedConfirmation()`, so `MessageService` and `ConfirmationService` translate `summary`, `detail`, `header`, `message`, and labels automatically. Feature code should keep using keys or Spanish source text.

## Adding a translation

1. Add the same key to both `es.json` and `en.json` of the owning feature.
2. If the file is new, import it in `dictionaries.ts` for both languages and add it to the merged maps.
3. Use the key in the template, component, message, or route title.
4. Run the coverage test.

```bash
bun run test:run src/app/core/i18n/translation-coverage.spec.ts
```

The coverage test verifies:

- Spanish and English have exactly the same keys.
- No value is empty.
- Core shared actions remain translated.

---

## Rules

1. Do not hardcode user-facing text in templates or components.
2. Keep keys namespaced by area and feature.
3. Add keys in both languages in the same change.
4. Keep feature messages in the feature `messages/` folder, not in `shared`.
5. Do not translate technical identifiers, API codes, or permission codes.
6. When a key is missing, the service falls back to Spanish, then to a readable catalog label, then to the raw key.
